# Core AI Gemma

The foreground engine is adapted from [Assist at 6a26dcf](https://github.com/ales27pm/assist/tree/6a26dcf27042d73833d8ce5b51178bdeb5f17562/mobile/ios/Assist/Inference). Lumen targets iOS 27.1; the real Gemma engine requires a physical device. Simulator builds expose typed unavailability and can exercise injected runtime tests.

In Settings → Local Gemma, import a fully downloaded local Gemma 4 E2B Core AI text-export folder. The package must contain `metadata.json`, the main `.aimodel` directory with matching `main.mlirb` / `main.hash`, PLE sidecar, and `tokenizer/tokenizer.json`, `tokenizer/tokenizer_config.json`, `tokenizer/chat_template.jinja`. The tokenizer identity is `google/gemma-4-E2B-it`, with an exported context of 8,192 or 32,768 tokens. Lumen does not download or bundle model weights. Obtain the export under its publisher's license and access requirements.

Import copies the folder into app-owned Application Support storage, checks paths and file identities, and atomically publishes the installation. Replacement needs enough free storage for both copies. Every cold load verifies the copied SHA-256 inventory; these hashes detect changes to imported bytes and do not certify publisher provenance, model quality or ANE placement. Model import, startup, passive diagnostics, and background maintenance never specialize or prompt the model.

The shared Gemma and text-embedding package reader hashes and copies at most 1 MiB per iteration. A local autorelease pool encloses the complete read/hash/write operation so temporary Foundation buffers are released after each block, including when an error or cancellation unwinds the operation. Directory traversal, no-follow opens, file mutation checks and atomic installation publication remain enforced.

Directory inventory reads entries progressively and admits at most 4,096 entries, including the root, before allocating additional paths. Each entry has its own autorelease pool and cancellation check. Both installers inspect every source file size and the aggregate quota before creating an owned copy; the actual opened copy source is checked again against the remaining quota before creating its output. Text embeddings also require the exact pinned byte count, followed by the existing SHA-256 verification. A source that grows or changes during copying still fails the final integrity checks.

Before a new installation, while its replacement gate is closed, recovery removes abandoned `.import-<uuid>` folders and inactive UUID installations within that model's owned root. A valid active installation is retained; an unreadable/corrupt pointer conservatively retains UUID installations until a later valid pointer allows their classification. Unknown names and root symlinks are preserved, nested symlinks are never followed, and source folders and Apple compilation caches are outside recovery. Enumeration, removal work, path length and open descriptors are bounded; cancellation or an excessive tree stops recovery with an error. Recovery runs during explicit installation, not at launch or passive settings inspection.

Both settings sections own their operation task and expose cancellation. Leaving the section, leaving the active scene, entering background, or receiving a memory warning cancels the operation. Busy state remains set until the service's worker has actually drained, and results from an earlier appearance cannot overwrite a later one. Gemma preference changes and removal check cancellation before acquiring the replacement gate and after draining the previous model, before committing a mutation.

“Use Gemma by default” is enabled on new installations. Missing or failing selected Gemma packages produce explicit errors. Disable the switch to use the existing llama/fleet configuration. Automatic fleet downloads are suppressed while supported Core AI Gemma is selected; embeddings retain their separate existing runtime and identity. Importing Gemma does not supply an embedding model or role LoRA adapters.

`CoreAIGemmaService` owns model, tokenizer, KV state and cancellation behind one actor and an operation latch. Requests use the local tokenizer's chat template, actual token-count preflight, exported graph/context checks, bounded output budgets, declared EOS IDs, full-prefix decoding, and a fresh KV state for every turn. Cancellation drains the active operation before unload or replacement; memory warnings unload Gemma. Chat memory is reclaimed from llama only when its generations are quiescent. Prompt assembly uses the loaded bundle's validated 8K or 32K capacity. Core AI sampling forwards temperature; llama-specific top-P and repetition settings are not applied to Gemma and are hidden in this mode.

Gemma mode has one generative assistant for chat, tool planning and answers. Plain chat and tool-enabled chat both enter the same kernel; “Allow tools” controls host execution without selecting another model. Legacy principal/sub-agent model pipelines are redirected before their fleet loops, and background maintenance cannot select a substitute model. Deterministic routing and the permission/approval state machine remain host logic. The auxiliary learned intent classifier is bypassed. Fleet, chat/LoRA activation and unsupported sampling controls are hidden in Gemma mode; embedding installation and selection remain available.

At explicit foreground chat/voice preparation, Lumen can load the already selected local embedding file independently of Gemma. Missing selection, file, resource admission or load failure remain diagnostic states; the memory backend is not silently substituted and existing memories/indexes are not erased. No embedding model is downloaded at launch. An independent optional [EmbeddingGemma 2 text embedding provider](COREAI_TEXT_EMBEDDINGS.md) is available after explicit import/selection. It does not add another generator; the existing GGUF embedding backend stays selected by default. Earlier [300M candidate research](COREAI_EMBEDDING_RESEARCH.md) remains separate.

Both text and structured requests pass through `AssistantKernel`. The tokenizer template explicitly disables thinking; canonical Gemma thought channels are also removed before callbacks or JSON parsing, and incomplete/control-only output fails closed. Gemma JSON is untrusted text: the existing executor validates its schema, tool availability, policy, permissions and approval, then feeds trusted observations into subsequent turns. Core AI does not attach executor LoRA adapters or enforce llama's native grammar. A failed load, preflight, generation, empty response or cancellation cannot become a repaired tool action. The kernel receives complete text snapshots; this integration does not add token-by-token UI delivery.

Dependencies are pinned to the Assist versions: `CoreAILM` from `apple/coreai-models@9db747612f972001279f02adb04d3ef982310d0e` and `Tokenizers` from `huggingface/swift-transformers@eed7264ac5e4ec5dfa6165c6e5c5577364344fe4`. The existing SwiftLlama pin is preserved. Use Xcode and an iOS SDK compatible with these packages and the iOS 27.1 deployment target. The pinned CoreAILM package declares iOS 27.0 as its minimum; the app uses iOS 27.1 as its release baseline. Framework import/type checks do not establish that the complete app or imported model runs successfully.

Validation on the Linux integration host is limited to source parsing, Python/static contract checks and patch review. For full-app validation, run the documented `xcodebuild ... build-for-testing` checkpoint on macOS, then the focused suites `CoreAIGemmaPolicyTests`, `CoreAIGemmaModelStoreTests`, `CoreAIGemmaRuntimeTests`, `CoreAIGemmaSingleModelTests`, `CoreAIGemmaPresentationPolicyTests`, `GemmaMemoryEmbeddingPolicyTests`, `SelfModelSnapshotTests`, `RuntimeRouterTests`, `LlamaGenerationCancellationTests`, and `ModelLoaderPolicyTests`. Separately qualify model import/load, text, tool approval, cancellation, replacement and memory pressure on a physical iPhone. Signed archives, TestFlight, model quality, 32K retrieval and Neural Engine execution require their own fresh evidence.

For the shared package and operation boundaries, run `bash scripts/run_coreai_package_io_tests.sh` on macOS with Swift 6.2 or later. It compiles the production filesystem helper, both stores, recovery, configuration policy, cancellation bus, operation owner and Gemma settings view in a temporary dependency-free package, using Swift language mode 5 and the app's MemberImportVisibility feature. Inference-service collaborators and view styling are test doubles; no model is loaded. The tests exercise real temporary installations, integrity rejection, quotas, interrupted-installation states, preservation of active data and external targets, deep recovery, replacement admission and operation cancellation/draining. The Gemma view is compiled; no SwiftUI flow is executed.

The isolated memory tests run copy and hash-only operations on a sparse 128 MiB file with a partial final block, and inventory a 32,768-file folder, inside detached tasks and outer autorelease pools. Each operation must retain less than 64 MiB of additional physical footprint before its outer pool drains. These assertions measure retained memory at completion, not the peak during the operation. They do not qualify the full iOS app, model inference, or iPhone memory limits.

On October 22, 2026, the native Darwin regression failed before the pool fix (`be87af57`): copy retained an additional 124 MiB and hash-only retained 112 MiB. With the same tests and toolchain, the fixed helper (`08f1b341`) passed all six tests and both measurements reported zero additional retained footprint at completion. The executor used Xcode 26.3, Swift 6.2.4 and the macOS 26.2 SDK on Intel; this result is a filesystem regression check, not an iPhone peak-memory or model-runtime benchmark.

The follow-up native run of the expanded harness passed 53 Swift Testing cases and 11 XCTest cases, including operation ownership and both stores. A separate five-case storage comparison, using identical synthetic fixtures and unmodified production sources from each commit, failed all five cases before the storage fixes (`3be5a44a`) and passed all five afterward (`7998c178`). It covers wrong-size admission, interrupted installation states and cancelled removal; it simulates files left at interruption boundaries rather than forcibly terminating an iPhone process. Fresh-process inventory probes of the bounded helper (`614da20f`) measured maximum RSS of 6.12 MiB for 8,000 files and 6.23 MiB for 32,000, both rejected at the entry limit. The earlier helper measured 52.86 MiB and 149.54 MiB respectively. These component measurements do not establish full-app memory usage, native iOS compilation, device behavior or a new TestFlight release.
